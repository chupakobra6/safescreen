# Inbox

Назначение: хранить легкий поток входящих требований и корректировок Игоря без отдельной
project-management структуры.

## Файлы

- `igor-deltas.md` - существенные новые требования, решения, ограничения и изменения области.

## Правила

- Записывать только reusable требования и решения, которые помогут следующей сессии.
- Формулировать коротко: исходный ввод, нормализация, статус, связанные файлы или коммит.
- Не хранить приватные данные, credentials, cookies, payment data и одноразовые промежуточные
  заметки.
- Если требование уже отражено в коде или docs, указывать ссылку на файл или commit вместо
  отдельной параллельной системы планирования.
