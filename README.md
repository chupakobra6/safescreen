# SafeScreen

Идея: macOS-приложение для приватной демонстрации экрана. Пользователь шарит не реальный монитор,
а SafeScreen - отдельный экран/поток, где видны только выбранные окна и приложения. Приватные окна,
уведомления, лишние значки в Dock/menu bar и отвлекающие приложения в картинку не попадают.

Основной сценарий: браузерная звонилка или стрим получает SafeScreen как full screen. Снаружи это
должно выглядеть как обычная демонстрация монитора, но картинка собрана нами.

## Уровень 1: минимальный MVP

Цель: быстро доказать, что можно собрать чистую картинку.

Что делаем:

- macOS-приложение;
- захват экрана через ScreenCaptureKit;
- выбор окна или приложения, которое нужно скрыть;
- preview того, что увидит зритель;
- скрытие одного окна браузера при видимом втором окне браузера;
- базовая чистка Dock/menu bar/уведомлений в preview.

Результат уровня: окно SafeScreen Preview, которое уже можно вручную зашарить в звонке и проверить,
что лишнее не видно.

## Уровень 2: рабочий вариант для браузерной звонилки

Цель: сделать полноценный режим "шарю полный экран", но этим экраном является SafeScreen.

Что делаем:

- виртуальный дисплей `SafeScreen`;
- браузерная звонилка видит его как отдельный monitor/full screen source;
- пользователь выбирает именно этот экран в browser screen picker;
- SafeScreen рендерит разрешенные окна, чистый фон, безопасный Dock/menu bar или режим без них;
- браузерный benchmark: если браузерный прокторинг/агрессивная web-звонилка не видит лишние окна,
  значит обычная браузерная звонилка тоже не увидит;
- отдельный список ликов: приватные окна, уведомления, Dock-точки, menu bar, desktop files, фокус.

Результат уровня: рабочий SafeScreen Display, который можно использовать в браузерных звонках как
полноэкранную демонстрацию.

## Уровень 3: продуктовые фичи

Цель: добавить удобство и контроль вокруг рабочего SafeScreen.

Что делаем:

- профили: рабочий звонок, стрим, демо;
- быстрый hotkey "скрыть активное окно";
- список скрытых окон и приложений;
- локальная запись того, что видит собеседник;
- браузерное расширение, синхронизированное с приложением;
- открытая панель расширения: какие browser-сигналы видит сайт, что сейчас шарится, какие события
  происходят при переключении окон;
- режим подготовки перед звонком: проверить, что выбран SafeScreen, а не реальный монитор;
- звук отдельным треком после видео: скрытие звука конкретных приложений сложнее и не входит в
  первые два уровня.

Activity Monitor пока не трогаем вообще.

## Как разрабатываем со мной

Работаем короткими вертикальными шагами.

1. Берем один кусок из текущего уровня.
2. Я читаю текущую структуру проекта.
3. Даю короткий план: какие файлы трогаю и что должно получиться.
4. Реализую.
5. Проверяю самым близким способом: сборка, тест, запись экрана, browser benchmark.
6. Коммичу только свои изменения локально.
7. В финале пишу, что сделано, чем проверено и какой commit получился.

Первый нормальный coding-step:

```text
Сделать Level 1 skeleton:
- Swift/macOS app;
- ScreenCaptureKit capture одного display;
- выбор приложения для скрытия;
- preview window;
- без virtual display и без audio.
```
