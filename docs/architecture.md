# SafeScreen Architecture

SafeScreen - macOS-приложение для приватной демонстрации экрана. Пользователь работает на реальном
Mac, а в звонок или стрим отдает отдельный SafeScreen output, собранный из разрешенных окон и
очищенный от лишних визуальных признаков.

## Форма продукта

Основной сценарий: браузерная звонилка или OBS получают SafeScreen как full-screen source. Для
зрителя это выглядит как обычная демонстрация монитора, но пиксели собраны нашим compositor.

```text
real display + windows
        |
        v
ScreenCaptureKit capture
        |
        v
privacy compositor
        |
        v
SafeScreen Preview / SafeScreen Display
        |
        v
browser call, stream or OBS
```

Главное направление - SafeScreen Display: виртуальный дисплей, который браузер может выбрать как
monitor/full-screen source.

## Этап 0: свой скрываемый браузер

Цель: быстро проверить самый простой сценарий из чата - пользователь открывает нужные страницы не в
обычном Chrome/Safari, а в нашем легковесном macOS-браузере, и это окно не попадает в браузерный
screen share.

Это не заменяет SafeScreen Display. Этап 0 скрывает только собственное окно приложения. Он не
скрывает Telegram, чужие окна Chrome, IDE, PDF и другие приложения.

Делаем:

- нативное macOS-приложение на Swift;
- `WKWebView` как встроенный браузер;
- одно основное окно с веб-страницей;
- режим поверх всех окон;
- hotkey показать/спрятать окно;
- нейтральный menu bar/background режим без Dock-иконки;
- content protection для собственного окна, чтобы проверить скрытие в браузерных звонках;
- test page/звонок в браузере, где пользователь шарит экран и проверяет, что окно этапа 0 не видно.

Что проверяем:

- Google Meet / браузерный WebRTC screen share не показывает окно этапа 0;
- окно остается удобным для чтения и ввода;
- переключение окна не создает визуальных ликов в шаринге;
- поведение стабильно на текущей macOS и основных браузерах.

Результат: маленький рабочий прототип "приватного браузера" для браузерных звонков. Если он
подтверждает спрос, остаются уровни 1-2 для полноценного SafeScreen, который скрывает любые
выбранные окна.

## Уровень 1: минимальный MVP

Цель: быстро доказать, что можно собрать чистую картинку.

Делаем:

- macOS-приложение;
- ScreenCaptureKit capture одного display;
- выбор приложения или окна для скрытия;
- preview того, что увидит зритель;
- сценарий "одно окно браузера скрыто, второе окно браузера видно";
- базовая чистка Dock/menu bar/уведомлений в preview.

Результат: SafeScreen Preview можно вручную зашарить в звонке.

## Уровень 2: рабочий вариант для браузерной звонилки

Цель: сделать workflow, где пользователь выбирает SafeScreen как полный монитор.

Делаем:

- виртуальный дисплей `SafeScreen`;
- browser screen picker видит его как monitor/full-screen source;
- SafeScreen рендерит разрешенные окна, чистый фон и безопасный Dock/menu bar или режим без них;
- browser benchmark показывает, что web page получает именно SafeScreen source;
- проверяем лики: приватные окна, уведомления, Dock-точки, menu bar, desktop files, визуальная смена
  фокуса.

Результат: пользователь заходит в браузерный звонок и шарит SafeScreen как full-screen source.

## Уровень 3: продуктовые фичи

Цель: добавить удобство и контроль вокруг рабочего SafeScreen Display.

Делаем:

- профили: рабочий звонок, стрим, демо;
- hotkey "скрыть активное окно";
- список скрытых окон/приложений;
- локальная запись того, что видит собеседник;
- браузерное расширение, синхронизированное с приложением;
- открытая панель расширения: что сейчас шарится, какие browser-сигналы видит сайт, какие события
  происходят при переключении окон;
- pre-call check: выбран SafeScreen, а не реальный монитор;
- звук отдельным треком после видео.

Activity Monitor пока не трогаем.

## Компоненты

### Capture

ScreenCaptureKit читает реальный экран и доступные окна. Для скрытых приложений/окон используем
content filters там, где это подходит.

### Privacy Compositor

Compositor собирает shared frame из разрешенного контента. Он не обязан зеркалить реальные системные
зоны, где могут быть лики. Он отвечает за:

- разрешенные окна;
- чистый фон;
- безопасный или отсутствующий Dock/menu bar;
- отсутствие уведомлений в shared-картинке;
- cursor rendering;
- layout, когда скрытые окна перекрывают видимые.

Идеи из чата для compositor:

- не зеркалить настоящий Dock, если там видны точки запущенных приватных приложений;
- не зеркалить настоящий menu bar, если там есть иконки, Focus/VPN/recording indicators или бейджи;
- уметь рисовать safe Dock/menu bar или работать в режиме без системного chrome;
- отрисовывать собственный cursor и не показывать движения внутри скрытой области;
- если скрытое окно перекрывает разрешенное, не пытаться "дорисовать" то, чего система не отдает:
  лучше показать чистый фон, warning или перестроить layout разрешенных окон.

### Output

Уровень 1 отдает preview window. Уровень 2 отдает SafeScreen virtual display. OBS source, virtual
camera и audio routing - возможные следующие направления, но не первый target.

Идеи из чата для virtual display UX:

- virtual display не должен становиться primary display, иначе новые окна и системный UI могут
  уехать на невидимый экран;
- для одного физического монитора нужно решить "убегание" курсора: геометрией дисплеев или
  ограничением курсора во время трансляции;
- в screen picker пользователь выбирает SafeScreen display; зрители не видят picker, поэтому важно
  не имитировать единственный дисплей, а сделать выбор понятным и безопасным;
- локальная запись "что видел собеседник" нужна как простой способ проверки.

### Browser Companion

Браузерное расширение относится к уровню 3. Его задача - открыто показывать пользователю, что видит
страница: какой source зашарен, какие browser events происходят и соответствует ли текущий setup
SafeScreen workflow.
