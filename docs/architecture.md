# SafeScreen Architecture

SafeScreen - macOS-приложение для приватной демонстрации экрана. Пользователь работает на реальном
Mac, а в звонок, стрим или OBS отдает SafeScreen output: картинку, где есть только выбранные окна и
нет приватных приложений, уведомлений, desktop files, реального Dock/menu bar и лишних визуальных
следов.

## Смысл продукта

Идея из чата: пользователь может шарить "полный экран", но не отдавать реальный монитор. Например,
одно окно браузера видно, другое окно браузера скрыто; Telegram, отвлекающие приложения и их
признаки не попадают в shared-картинку.

Цель - чтобы снаружи это выглядело как обычный full-screen share, но звонок получал SafeScreen
output, а не физический экран.

## Варианты продукта

Быстрый прототип: собственный легковесный macOS-браузер на `WKWebView`, окно которого скрывается от
браузерных звонилок. Это закрывает сценарий "браузер внутри приложения не виден в шаринге", но не
решает задачу скрытия любых чужих окон.

Основной продукт: SafeScreen Display. Приложение захватывает экран через ScreenCaptureKit, исключает
выбранные окна/приложения, собирает очищенную картинку в compositor и отдает ее как отдельный
display/output. В Meet, Zoom, браузерной звонилке или OBS пользователь выбирает SafeScreen как
full-screen source.

Будущий companion: браузерное расширение или открытая панель, которая показывает пользователю, что
видит сайт, и помогает контролировать browser-visible события вроде focus/blur. Это идет после
рабочего видео-flow.

Не сейчас: Activity Monitor/process hiding и звук. Сначала нужен понятный видео-output.

## Поток данных

```text
real display + windows
        |
        v
ScreenCaptureKit capture
        |
        v
SafeScreen compositor
        |
        v
SafeScreen Preview / SafeScreen Display
        |
        v
browser call, stream or OBS
```

## Compositor

Compositor собирает shared frame из разрешенного контента:

- включает выбранные окна/приложения;
- исключает приватные окна/приложения;
- рисует чистый фон вместо лишних областей;
- не зеркалит настоящий Dock/menu bar, если там есть приватные признаки;
- не показывает уведомления и desktop files;
- рендерит cursor так, чтобы движения внутри скрытых областей не раскрывали приватный контент;
- если скрытое окно перекрывает разрешенное, не пытается восстановить недоступные пиксели, а
  использует чистый фон или перестраивает layout.

Браузерный screen share и браузерный прокторинг используются как benchmark: если страница получает
только SafeScreen output и не видит лишние визуальные сигналы, этот же подход подходит для
агрессивных браузерных звонилок.
