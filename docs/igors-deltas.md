# Нормализованные выводы Игоря

Назначение: быть единым источником правды по нормализованным выводам из прямых входов Игоря.

## Связанные документы

- [../AGENTS.md](../AGENTS.md) - правила работы агентов, область документации и проверки.
- [architecture.md](architecture.md) - актуальная продуктовая и техническая архитектура SafeScreen.
- [runbook.md](runbook.md) - команды запуска, сборки, проверок и ручных сценариев.
- [../materials/inbox/2026-06-11-direct-chat-prompts.md](../materials/inbox/2026-06-11-direct-chat-prompts.md)
  - дневной склад сырых прямых сообщений за 2026-06-11.

## Как обновлять

- Этот документ один для всех дней и обновляется при каждом новом смысловом входе Игоря.
- Дневные файлы `materials/inbox/YYYY-MM-DD-direct-chat-prompts.md` хранят только сырые прямые
  сообщения Игоря.
- Выводы из новых дневных inbox-файлов переносить сюда, сверять с [architecture.md](architecture.md)
  и исправлять существующие пункты, если новое решение заменяет старое.
- Этот документ не является историческим логом. Если вывод устарел, его нужно заменить актуальной
  формулировкой, а историю оставить в inbox и git history.
- Прямые инструкции Игоря важнее старых выводов ассистента и внешних ответов. Поздняя прямая
  инструкция важнее ранней, если они конфликтуют.

## Входы и inbox

- В дневных inbox-файлах должны лежать только прямые сообщения Игоря, без ответов ассистента.
- Inbox фиксирует не любой ввод, а только смысловые сообщения: требования, идеи, решения, правки,
  уточнения и проектную информацию.
- Чистые команды, статусы и действия без долговременного смысла в inbox не добавляются.
- Сырая история очищается по этому фильтру: чистые команды обслуживания без самостоятельного
  проектного смысла не хранятся для истории.
- Сообщения сохраняются хронологически внутри дневного файла.
- Полный сырой транскрипт хранить не нужно.
- Перед финалом по документной задаче нужно проверить, что свежий вход сохранен в дневном inbox и
  учтен в этом документе.

## Продуктовая рамка

- SafeScreen - ПО для приватности; не писать бесконечные общие оговорки про безопасность и не
  считать обычную продуктовую работу контекстом вредоносного ПО.
- Конкретные ограничения macOS, браузеров, разрешений и политик можно указывать коротко, когда они
  реально влияют на решение.
- Основное направление - дисплей SafeScreen: виртуальный дисплей, который браузер или OBS выбирает
  как источник полного экрана.
- Невидимый оверлей не является основным режимом: цель проекта - скрывать разные выбранные окна и
  приложения в разных звонках.
- Activity Monitor пока не трогаем.
- Звук - отдельный будущий трек после видео.

## Этап 0

- Этап 0 - быстрый прототип собственного браузера, который скрывает только свое окно от браузерных
  звонилок.
- Этап 0 нужно оценивать как быстрый агентно-разрабатываемый прототип на SwiftPM/AppKit, а не как
  Xcode GUI-проект.
- Xcode GUI не является обязательным для полностью агентной разработки; базовый рабочий процесс -
  CLI/SwiftPM через Command Line Tools, с Xcode GUI только как дополнительным инструментом для
  профилирования или подписи, если это позже понадобится.
- Браузер этапа 0 по умолчанию остается на `WKWebView`; Chromium/CEF/Electron/Tauri - только если
  реально понадобится Chrome-движок или расширения Chrome, потому что это резко утяжеляет прототип.
- Для защиты от события blur в браузере без расширения использовать пассивный режим `NSPanel` +
  `.nonactivatingPanel`: чтение и скролл без захвата фокуса; ввод текста требует фокус клавиатуры и
  может вызвать событие blur.
- Пассивное чтение скрывается через macOS-свойства окна: `NSPanel`, `.nonactivatingPanel`, запрет
  захвата фокуса клавиатуры там, где ввод не нужен, `sharingType = .none`, уровень окна и поведение
  в Spaces и полноэкранном режиме.
- Тест этапа 0 - Google Meet, Telemost, Zoom Web и браузерный прокторинг; десктопный Zoom не
  является целевым тестом для `NSWindow.sharingType = .none`.
- Ручной результат этапа 0: приложение не видно в Google Meet, Telemost и браузерном прокторинге;
  прокторинг не выдал уведомление о переключении фокуса на стороннее приложение.

## Этап 0.1

- Этап 0.1 - простое браузерное расширение для основного браузера, которое базово нормализует
  видимые странице сигналы активности вкладки и окна.
- Минимум этапа 0.1: Manifest V3 для Chromium-браузеров, контент-скрипт на `document_start`,
  список разрешенных доменов или ручной переключатель, нормализация `document.hidden`,
  `document.visibilityState`, `document.hasFocus()` и событий `visibilitychange`, `blur`, `focus`,
  `pagehide`, `pageshow`.
